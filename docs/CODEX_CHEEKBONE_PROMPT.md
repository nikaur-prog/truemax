# Task for Codex: fix the cheekbone / bizygomatic landmark, then continue launch

You are working in the TrueMax repo (a client-side facial-analysis web app,
Vite + TypeScript, deployed on Vercel). Branch: create a fresh branch off
`main`. Everything runs on-device; **no photographs are ever committed** — the
repo holds coordinates and quantile tables only. Do not weaken the CSP in
`vercel.json` (`connect-src 'self'`), do not add surgery/supplement/prescription
advice, do not put a Supabase `service_role` key in client code.

## Part A — the cheekbone fix (the measurement bug)

### The problem

`src/engine/geometry.ts` defines `ZYGO_R: 234, ZYGO_L: 454`. These are
MediaPipe's **widest face-oval** landmarks — they sit at ear/sideburn level, not
on the zygomatic arch (the cheekbone). So `bizygo` (face width at the
cheekbones) is really "face width at the ears".

`bizygo` is the denominator of six metrics in `src/engine/metrics.ts`:
`fwhr`, `cheekboneHeight`, `jawCheekRatio`, `eyeSeparationRatio`,
`fifthsEyeRatio`, `facialIndex`.

This is currently **internally consistent** (every face uses the same landmark,
scored against norms built from that same landmark), so scores are comparable
between people. The defect is *validity*: any claim that these numbers describe
the cheekbone is wrong, and the measurement overlay in
`src/ui/measureOverlay.ts` draws the span at ear level, which looks wrong to
anyone who knows their own face.

### What to do

1. **Choose better landmarks for the malar prominence / zygomatic arch.**
   Investigate the 478-point mesh. Candidate pairs to evaluate include the
   116/345 and 111/340 regions (mid-cheek), but do not trust this list — verify
   against the reference face renders (step 2). Pick the pair whose span sits on
   the widest bony cheek point in a front photo, symmetric about the midline.

2. **Validate visually.** Use `calib.html` (the calibration bench) or a small
   Playwright script that renders the chosen landmarks over 8–10 reference
   faces, and confirm the span lands on the cheekbone across face shapes, not
   the ears and not the mid-cheek soft tissue.

3. **Re-derive the affected metrics' distribution constants.** Each metric in
   `metrics.ts` has a `dist[sex] = { mean, sd }`. Changing the landmark changes
   every one of the six metrics' raw values, so their means and SDs must be
   recomputed from the reference set, not hand-tweaked.

4. **Regenerate `AGG_NORM`.** This is mandatory and is the step that cannot be
   skipped or faked. `src/engine/aggNorm.ts` is generated by
   `tools/normalize.mjs`, which drives the real engine over the reference photo
   set. Run the pipeline (see `docs/LAUNCH.md` → "Regenerating the norms"):

   ```
   node tools/fetch-photos.mjs      # populates .calib/ — needs open internet
   node tools/scan-celebs.mjs
   node tools/apply.mjs
   node tools/normalize.mjs         # rewrites src/engine/aggNorm.ts
   npm run build
   ```

   `.calib/` is gitignored and not in the repo; `fetch-photos.mjs` rebuilds it
   from the manifest of public figures, which needs unrestricted internet. **This
   is why the fix cannot be completed in a sandbox with no photo set or no open
   network — it is the specific reason this task was handed to you.**

5. **Sanity-check the scale after regenerating.** Median overall score must stay
   ≈ 5.0 (50th percentile) by construction. If a metric's distribution collapsed
   or a landmark returns NaN on some faces, the quantile table will show it.

6. **Update the overlay label copy** in `measureOverlay.ts` if the span now
   genuinely tracks the cheekbone — it can honestly say "cheekbone width".

7. `npx tsc --noEmit` and `npx vite build` green. Commit with a message that
   states plainly that norms were regenerated and why. Open a PR.

### If you cannot get the reference photos either

Then do NOT change the landmark — a landmark change without regenerated norms
breaks the 5.0-median scale, which is worse than the current honest-but-mislabelled
state. Instead: (a) leave the landmark, (b) correct the *labels and overlay* so
nothing claims "cheekbone" where it means "face width at ear level", and (c)
open an issue documenting the landmark debt. Half-doing this fix is the one
outcome to avoid.
